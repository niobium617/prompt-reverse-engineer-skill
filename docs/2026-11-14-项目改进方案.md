# APS 项目改进方案（2026-11-14）

> 状态：已实施阶段 0–3，v2.1.0 已发布（2026-11-14）。本文描述方案与验收标准，实施记录见第 12 节。
> 基线：`main` = `86e67e4` 内容（与特性分支树一致），`tools/verify.py` 24/24 PASS，10 个目标模型、11 个模板、6 个脚本。
> 参考：仓库内审（P0–P3）+《GPT Image 专项优化改进设计方案 v1.0》评审结论。

---

## 0. 摘要

本方案分两条线：

1. **工程线**：修 P0 资源问题、消除文档/版本/安装包漂移、补齐校验与 CI。
2. **能力线**：把 GPT Image 从"通用图片模板"升级为"五任务模式 + 扁平视觉契约"，不重构目录、不引入嵌套结构、不新增后端。

硬约束（违反即不可实施）：

| 约束 | 证据 | 方案应对 |
|---|---|---|
| 模板加载只扫顶层 `*.json` | `prompt_compiler.py:280` | 不采用方案原文的 `templates/image/gpt_image/` 目录 |
| 占位符只认单层 `{field}`，`dict` 会被 `str()` | `prompt_compiler.py:154,380` | 契约全部压平；编译器显式拒绝 dict 值 |
| `kind_requires` 只能引用 `KNOWN_FIELDS` | `prompt_compiler.py:268` | 新字段同步进 `KNOWN_FIELDS`，校验改用 `allowed_fields` |
| 编译默认渲染模板内全部 kind | `prompt_compiler.py:462` | 新增 `--kind` 显式选择，缺省保持旧行为 |

改动集中在 9 个既有文件 + 2 个新文件；不触碰安装层以外的平台适配产物（由 `install.py` 重新生成）。

## 2. 目标与原则

### 2.1 目标

| 维度 | 现状 | 目标 |
|---|---|---|
| 视频健壮性 | 长视频可能 OOM，临时文件堆积 | 120s/1080p 峰值内存 < 300 MB，退出后临时目录为空 |
| 契约一致性 | 文档、示例、生成包三处漂移 | 由脚本生成/校验，CI 拦截 |
| GPT Image | 单模板单任务 | 5 任务模式，任务与 kind 一一对应 |
| 视觉还原 | 主体+风格概括 | 主体位置/占比/景别/空间/材质/编辑边界 |
| 可验证性 | 24 项断言 | 26 项（阶段 1 后）→ 38–40 项（阶段 2 新增 12–14 项） |
| 版本发布 | tag 与清单脱节 | 单一 `VERSION` 源，发布检查通过 |

### 2.2 原则

1. 单一事实源不变：`prompt-reverse-engineer-skill/` 仍是唯一源。
2. 模板平铺不变：`assets/templates/*.json` 一文件一模型，零代码注册。
3. 确定性不变：新增字段全部由 Agent 提供，编译器不做推断、不引入时间/随机。
4. 纯插件不变：不新增后端、不要求 API Key、不调用生成 API。
5. 向后兼容：不传 `--kind` / `task_type` 时，行为与现在一致。
6. 不把用户提供的具体素材示例写入技能文档，示例统一用仓库中性的"雨夜伞"素材。

## 4. 改造后架构（概念图）

```
用户输入（文本/图片/视频/叙事）
  ↓
L1 确定性脚本  ── local_features（不变；视频增加 workdir/内存治理）
  ↓
L2 Agent 语义分析 ── semantic_analysis（扁平契约 + task_type + 置信度标记）
  ↓
编译器 prompt_compiler.py
  ├─ 校验层：modality/kind 必填、类型、枚举、去重、dict 拒绝
  ├─ 选择层：task_type → kind；--kind 覆盖；缺省 = 旧行为（全部 kind）
  ├─ 渲染层：模板占位符（平铺字段）
  ├─ 评分层：全局六维（不变）+ GPT Image 审查清单（附加）
  └─ 安全层：黑名单 + 注入提示（不变）
  ↓
输出：元信息卡 + 摘要 + Prompt 列表 + 评分表 + 建议
  ↓
（可选，P2）用户回传生成图 → analyze_image 两次 → 差异清单 → 修正 Prompt
```

### 4.1 关键设计决策

| 决策 | 选择 | 理由 | 被否方案 |
|---|---|---|---|
| 模板目录 | 保持 `assets/templates/*.json` 平铺 | 加载器、安装器、豆包打包、verify 均依赖顶层扫描 | `templates/image/gpt_image/` 分层 |
| 契约形态 | 扁平字段 | 编译器只支持 `{field}`，`dict` 会漏 repr | §11 嵌套 `visual_analysis.subject.*` |
| 任务选择 | `task_type` + `--kind` | 显式、可测、向后兼容 | 自动渲染全部 kind |
| 评分 | 全局六维 + 审查清单 | 不动 `DIMENSIONS`/`SUGGESTIONS` 双镜像 | 第二套评分引擎 |
| 参考图 | `reference_images: string[]` | 无需新文件、可渲染、可校验编号 | 独立 `reference_roles.json` |
| 迭代 | 文档工作流 + 复用 `analyze_image` | 不新增后端/API | 自动调用生成接口 |

## 5. 详细设计

### 5.1 P0：视频分析资源治理

**目标行为**

1. 两遍顺序解码：第一遍算直方图差与亮度，第二遍按已知分镜取首帧/中点帧；不做逐镜头 seek，不缓存全部抽样帧。
2. 内存只保留当前帧、每镜头首帧灰度与当前镜头中点帧，随取随释放。
3. 本地文件直接交给 OpenCV 读取，不复制、不整文件入内存；先 `os.path.getsize` 检查 `--max-bytes`。
4. stdin / URL 先落盘到工作目录，分析结束后删除副本；关键帧保留。
5. 工作目录：`--workdir DIR`，默认仓库 `.tmp/`（安装态回退系统临时目录）；关键帧写入 `video_<sha8>/keyframes/`，输出 JSON 给出绝对路径。
6. 同一输入重复运行时先清理旧关键帧，避免 stride/时长变化留下多余文件。
7. 输出 JSON 的字段、分桶、排序保持现状，确保同一输入两次运行逐字节一致。

**验收**

- 120s / 30fps / 1080p 样本：峰值 RSS < 300 MB（当前为 GB 级）。
- stdin / URL 分析后 `video_<sha8>/input.bin` 不存在；关键帧保留（Agent 需读取）。
- 同一输入两次输出 sha256 一致。
- `verify.py` 新增断言：`--workdir` 生效、临时副本清理、超限退出 3、输出幂等（沿用现有幂等断言）。

### 5.2 P1：一致性与发布

**README**

- 删除 `requests` 行与安装命令中的 `requests`。
- 依赖表改为：`opencv-python`（图片/视频）、`pillow`（图片）、`numpy`（数值），均"按模态可选"。
- `README.md:251` 的"仅视频关键帧写入系统临时目录"改为"写入 `--workdir`，默认项目 `.tmp/`，运行后清理"。

**install.py**

- `build_doubao_body` 扫描 `prompt-reverse-engineer-skill/scripts/*.py`，生成脚本清单与数量，删除硬编码"4 个"。

### 5.3 GPT Image 专项

#### 5.3.1 五种任务模式 ↔ kind

| task_type | kind | 用途 | 门控（`kind_requires`） |
|---|---|---|---|
| `text_to_image` | `prompt` | 文生图（标准/优化模式） | 无 |
| `image_recreation` | `recreate` | 高保真复刻 | `subject` + `subject_position` |
| `image_editing` | `edit` | 局部/整体编辑 | `modification_scope`（替代现 `target_style`） |
| `reference_guided` | `reference_guided` | 多图参考生成 | `reference_images` |
| `image_composition` | `compose` | 多图融合 | `reference_images` + `spatial` |

保留 `params` kind 作为独立记录；`--kind` 未指定时行为与现在一致。`task_type` 与 `--kind` 同时给出且不匹配 → 退出 4。

#### 5.3.2 扁平契约增量（写入 `prompt_framework.md` §2.3）

| 字段 | 类型 | 必填 | 说明 / 示例（中性素材） |
|---|---|---|---|
| `subject_position` | string | 复刻/参考/融合必填 | 九宫格+相对位置，如 `center-right, slightly above the midline` |
| `subject_scale` | string | 否 | 主体占画面比例，如 `about 35% of frame height` |
| `shot_type` | string | 否 | 景别，如 `medium shot` / `close-up` / `wide shot` |
| `camera_angle` | string | 否 | 角度与视角，如 `low angle, eye level` |
| `spatial` | string | 复刻/融合必填 | 前/中/背景、遮挡、透视一句话 |
| `material` | string | 否 | 材质、纹理、反射、表面状态 |
| `preserve_constraints` | string[] | 编辑必填 | 必须保留，如 `["面部特征", "姿态", "构图"]` |
| `forbidden_changes` | string[] | 编辑必填 | 禁止变化，如 `["不得改变人物身份", "不得改变身体比例"]` |
| `modification_scope` | string[] | 编辑必填 | 允许修改范围，如 `["服装", "背景"]` |
| `reference_images` | string[] | 参考/融合必填 | 每项一行：`图1：identity_reference；提取：面部/发型；保留：构图；禁止迁移：服装` |
| `task_type` | string | 建议 | 五个枚举值之一 |
| `uncertainty` | string[] | 否 | 低置信度项及原因，不进入 Prompt 正文 |

复用既有字段：`subject`、`scene`、`style`、`lighting`、`color`、`composition`、`photo_params`、`quality_words`、`negative_words`、`target_style`、`text_content`、`reference_note`。

```json
      "edit": "Edit the provided image.\n\nChange: {target_style} ({modification_scope})\nPreserve unchanged: {preserve_constraints}\nDo not: {forbidden_changes}\nKeep all other content, composition, lighting, color and existing text exactly as is.",
      "reference_guided": "Create an image using the provided references.\n\nReference roles:\n{reference_images}\n\nSubject: {subject}\nSpatial layout: {spatial}\nStyle: {style}\nConstraints: use each reference only for its assigned role; do not transfer unlisted attributes.",
      "compose": "Compose a new image from the provided references.\n\nElement sources:\n{reference_images}\n\nPlacement: {subject_position}, {subject_scale}\nSpatial layout: {spatial}\nLighting and color: {lighting}, {color}\nMatch perspective, light direction, color temperature and material across all elements. Do not simply collage the references."
    }
  }
}
```

注意：`prompt` 中 `{shot_type}`、`{camera_angle}` 若未提供，由 `optional_fields` 置空后由 `clean_rendered` 清理空括号；需确认清理规则覆盖 `Composition: ... ()` 形式，否则在模板中拆成独立行。

#### 5.3.4 编译器改动

1. `KNOWN_FIELDS` 增加 5.3.2 的新字段（一行集合扩充）。
2. `template_errors` 第 268 行：`kind_requires` 校验改用 `allowed_fields`（`KNOWN_FIELDS | default_params | optional_fields`）。
3. `compile` 增加 `--kind KIND`：
   - 只渲染指定 kind；
   - 不存在该 kind → 退出 1；
   - 与 `task_type` 映射冲突 → 退出 4。
4. `task_type` → kind 映射：`text_to_image→prompt`、`image_recreation→recreate`、`image_editing→edit`、`reference_guided→reference_guided`、`image_composition→compose`。
5. `format_field` 遇到 `dict` 值 → 抛 `ValueError`，上层转退出码 4，消息指出字段名。
6. 编译前校验：
   - 必填字段按 modality/kind 检查；
   - `reference_images` 必须含"图N"编号且不重复；
   - `task_type` 必须在枚举内；
   - `uncertainty` 不得包含 `unknown` 值进入正文（仅提示）。

#### 5.3.5 编辑约束顺序

渲染顺序固定为：修改目标 → 保留约束 → 禁止变化 → "其余保持不变"。`preserve_constraints` 与 `forbidden_changes` 为空时，`edit` 不渲染（`kind_requires` 已门控 `modification_scope`，但仍建议编译期报缺字段而不是静默降级）。

#### 5.3.6 参考图角色

- 角色枚举：`edit_target`、`identity_reference`、`pose_reference`、`clothing_reference`、`style_reference`、`composition_reference`、`background_reference`、`object_reference`。
- 每项必须写清：编号、角色、提取内容、保留内容、禁止迁移内容、优先级。
- 角色无法确定且不同解释会明显改变结果时，Agent 先询问用户；不得臆测。
- 不新增 `reference_roles.json` 文件；信息全部在 `semantic_analysis.reference_images` 中，随分析 JSON 传递。

#### 5.3.7 置信度约定

- `observed`：直接可见，可进 Prompt。
- `inferred`：合理推断，进 Prompt 时加"（推测）"或放入 `uncertainty`，由 Agent 判断是否保留。
- `unknown`：不得写入 Prompt，只能进 `uncertainty`。
- 禁止为"显得专业"虚构镜头参数、灯具功率、材质成分。
- 编译器不计算置信度，只做结构校验（如 `uncertainty` 与正文重复时提示）。

#### 5.3.8 负向约束（GPT Image）

拆成三类自然语言约束，写入 `Constraints` 段：

1. Exclusion：`Do not include watermarks, unwanted text, additional people or unrelated objects.`
2. Preservation：`Keep the original facial features, expression, pose and body proportions unchanged.`
3. Modification boundary：`Only modify the clothing and background. Do not change the character or camera framing.`

不引入独立 Negative Prompt 参数；`negative_words` 只取关键排除项，不整段照搬。

#### 5.3.9 评分

- 第一阶段：全局六维评分不变；在输出末尾附加 **GPT Image 审查清单**（不参与总分）：
  - 核心视觉信息是否遗漏；
  - 是否有重复描述；
  - 是否有冲突指令；
  - 是否把推测当事实；
  - 参考图角色是否混淆；
  - 是否缺少保留约束。
- 第二阶段（可选）：在模板元数据增加 `score_profile`，仅当稳定后再改 `DIMENSIONS`；改动需同步 `prompt_framework.md` §3/§5 与 `SUGGESTIONS`。
- 明确文档表述：Prompt 评分 ≠ 生成图像相似度。

#### 5.3.10 迭代优化（P2）

- 工作流写入 `SKILL.md`：生成 Prompt → 用户生成图 → 回传原图与结果图 → 分别 `analyze_image.py` → Agent 按七维（主体/构图/空间/光影/色彩/材质/细节）列差异 → 只改最大偏差 → 保留已达标的约束。
- 不新增后端/API；不改编译器主链路。
- 可选后续：新增 `diff` 子命令，对两张图的 `local_features` 做确定性差值（颜色直方图距离、亮度/对比度、主体 bbox 位移、3×3 网格差异），输出 JSON 供 Agent 使用。
