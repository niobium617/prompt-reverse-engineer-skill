## 1. 结论

原方案与现有项目的**理念契合度高（约 85%）**，但**范围约为现有项目的 3–4 倍**，且第 8 节目录重构与现有硬约束冲突。本最终稿的处理原则：

1. **保留**：L1/L2 双层分析、平铺模板注册、单一事实源、确定性幂等、无后端/无 API Key、53 项离线断言。
2. **新增**：IR 契约文档与校验、模型/平台/能力三注册表（生成物）、`creative-platforms/`、Workflow 输入模态与只读解析。
3. **收敛**：平台数量从 25+ 收敛到首批 3 个；专业软件只做 L1 说明；L4 明确不做；工作流解析只覆盖 ComfyUI 公开 JSON。
4. **不改**：目录结构、模板加载方式、安装方式、豆包包结构、退出码语义、评分引擎。

相对原方案的裁剪结果：

| 原方案 | 最终稿 | 理由 |
|---|---|---|
| 25+ 平台全量铺开 | 首批 3 个（ComfyUI / Runway / LibTV） | 无生成/校验工具时手工维护不可持续 |
| 每平台深做工作流导入导出 | 只做能力声明与映射骨架 | 决策 D3 |
| L4 自动化执行 | 不做，只声明平台原生能力 | 决策 D2 + 现有"无后端/无密钥"硬约束 |
| 目录重构为 `core/ model_adapters/ …` | 保持现有目录，新增 `creative-platforms/` | 平铺模板、安装器、豆包打包、verify 均依赖现状 |
| 13 个平台 adapter 目录 | 3 个，先跑通规范 | 渐进式建设 |
| 音频分析 | 可选，仅 WAV/PCM 确定性信号 | 不引入 ffmpeg 重依赖 |

## 2. 升级后的架构

### 2.1 分层（只增不改）

```
输入层：文本 / 图片 / 视频 / 叙事文本 / 工作流文件（新增，仅 ComfyUI JSON）
   ↓
核心分析层：L1 确定性脚本 + L2 Agent 语义分析（不变）
   ↓
IR 层（新增）：Project / Subject / Scene / Visual / Shot / Prompt / Reference / Model / Parameters / Workflow / Assets
   ↓
模型适配层：13 个模板（不变，按需新增可灵等）
   ↓
平台适配层（新增）：creative-platforms/ —— 创作软件能力映射与人工搭建说明
   ↓
输出层：Prompt / 参数 / 分镜表 / 工作流分析报告 / 兼容性报告 / 操作说明
```

关键边界：

- **模型适配**决定 Prompt 与生成参数；**平台适配**决定工作流、节点与执行方式。两者不互相替代。
- 现有 `runway.json` 只是 **Runway Gen-4.5 模型**的 Prompt 模板，**不等于** Runway Workflows 平台适配。
- 平台适配层**不执行**任何 API，只输出映射与说明。

## 3. 统一中间表示（IR v1）

### 3.1 设计约束

- **不嵌套进 `semantic_analysis`**：编译器只认单层 `{field}` 占位符，IR 作为**信封上的模块视图**，`semantic_analysis` 仍是其子集。
- **向后兼容**：不传 IR 时行为与 2.3.0 完全一致；旧 fixtures 与旧模板输出逐字节不变。
- **确定性**：IR 不含时间戳、随机数；键排序，同输入两次输出一致。
- **置信度**：所有关键结论可带 `observed` / `inferred` / `unknown`；`unknown` 不进 Prompt 正文。

### 3.2 十一模块与现有字段映射

| IR 模块 | 现有字段/来源 | 缺口 | v1 处理 |
|---|---|---|---|
| **Project** | 元信息卡、CLI 参数 | 无项目级字段 | 新增可选 `project`：`name/type/goal/output_spec` |
| **Subject** | `subject`（图像）、`character`（视频）、`role/domain/audience`（文本） | 无统一命名 | 保留原字段，IR 视图聚合 |
| **Scene** | `scene`、`atmosphere`、`story`、`storyboard` | 无场景实体 ID | 由 `storyboard` / 场景化 JSON 派生，不新增必填 |
| **Visual** | `style/lighting/color/composition/photo_params/quality_words/material` | 无 | 聚合，不迁移 |
| **Shot** | `composition` 中的视角/景别 + `storyboard[].shot_size/camera_move/duration_s` | 无独立镜头对象 | IR 视图由 `storyboard` 派生 |
| **Prompt** | 编译器输出 | — | **输出层**，不进入 IR 输入 |
| **Reference** | `reference_images`、`video_references`、`reference_note`、`first_frame/last_frame/source_video` | 无统一资产 ID | IR 视图聚合，编号规则不变 |
| **Model** | `assets/templates/*.json` 元数据 | 无正式注册表 | `model_registry.json` 生成 |
| **Parameters** | `default_params` + `params` 块 + `aspect_ratio/duration` | 无统一参数集 | IR 视图聚合 |
| **Workflow** | 无 | 全部 | 新增可选 `workflow`：`nodes/links/assets/deps`；无则显式 `null` |
| **Assets** | 脚本返回的输入路径 | 无资产清单 | 新增可选 `assets[]`：`path/kind/role/sha256/relation` |

### 3.3 新增字段（全部可选，不改变旧契约）

| 字段 | 类型 | 说明 |
|---|---|---|
| `ir_version` | string | 固定 `"1.0"`；缺省按 1.0 处理 |
| `project` | object | 项目名称、类型、目标、输出规格 |
| `assets` | array | 资产清单：路径、类型、角色、关系；敏感路径只保留文件名 |
| `workflow` | object | 节点图；v1 仅 ComfyUI 只读解析产物 |
| `confidence` | object | 模块级置信度：`observed/inferred/unknown` + 依据 |

校验规则（`prompt_compiler.py ir validate`）：

- `ir_version` 非 `1.0` → 退出码 4；
- `workflow` 非空但缺 `nodes` → 退出码 4；
- `assets` 条目缺 `kind` 或 `sha256` → 退出码 4；
- 嵌套深度超过 IR 允许层级 → 退出码 4；
- 旧 JSON 无 IR 字段 → 直接通过，行为不变。

### 3.4 置信度推广

- 现状：`uncertainty` 仅图像（GPT / Muse）做标签校验。
- 目标：所有模态只要提供 `uncertainty`，每项都必须带 `observed:` / `inferred:` / `unknown:` 标签；`unknown` 项不得出现在任何 Prompt 正文。
- 兼容：不提供 `uncertainty` 时不强制；数组格式与现有示例保持一致。

## 4. 注册表与能力声明

### 4.1 三注册表（生成物，不手改）

| 文件 | 来源 | 内容 |
|---|---|---|
| `config/model_registry.json` | `assets/templates/*.json` | 模型 ID、展示名、厂商、版本、别名、模态、任务模式、能力等级、来源文档 |
| `config/platform_registry.json` | `creative-platforms/*/capability_map.json` | 平台 ID、展示名、能力等级、模态、工作流格式、API/自动化声明、依赖 |
| `config/capability_registry.json` | 上述两者汇总 | 每个模型/平台的支持项、不支持项、降级方案、核验日期 |

生成规则：

- `tools/gen_registry.py` 确定性输出：键排序、无时间戳、无绝对路径；
- `tools/verify.py` 断言注册表可由源文件逐字节复现；
- 注册表不得包含"可运行"表述。

### 4.2 能力等级（沿用原方案定义，收紧表述）

| 等级 | 本 Skill 是否提供 | 表述要求 |
|---|---|---|
| L1 Prompt 适配 | 是 | 生成目标平台提示词 |
| L2 配置适配 | 是（验证后） | 映射参数、参考素材、模型选项 |
| L3 工作流适配 | **部分：仅只读解析** | 可解析、分析并输出报告；不生成、不导入、不导出工作流文件 |
| L4 自动化执行 | **不做** | 平台原生能力照实声明，`supported_by_skill: false` |

红线：不得把"输出配置文件"写成"保证运行"；不得把网页端功能等同于开放 API；不得把推断出的模型/参数/工作流写成已知事实。

## 6. 工作流逆向范围（v1）

### 6.1 输入

- **仅 ComfyUI 公开 JSON**：API 格式（`{node_id: {class_type, inputs}}`）与 UI 格式（`{nodes, links}`）。
- 不支持：`.blend`、`.prproj`、`.psd`、`.aep`、剪映工程等闭源/高成本格式（见第 9 节）。
- 仅凭最终成品**不能**确定性还原制作过程；无工作流文件时，全部结论只能标 `inferred` 或 `unknown`。

### 6.2 解析与校验

| 项 | 行为 |
|---|---|
| 节点 | 读取 `id/class_type/inputs/outputs`，未知节点类型 → 警告（不阻断） |
| 连线 | 悬空连线、缺失输入 → 退出码 4 |
| 模型 | 模型文件名/采样器/LoRA/ControlNet 提取；缺失或未知 → 标 `unknown` |
| 依赖 | 自定义节点清单；版本未知 → 标 `unknown` |
| 循环 | 依赖成环 → 退出码 4 |
| 幂等 | 同一文件两次输出逐字节一致 |

### 6.3 输出

- `workflow_report.json`：节点、连线、模型、参数、素材、依赖、置信度、问题清单；
- Markdown：人工搭建说明 + 不兼容项 + 替代方案 + 降级等级；
- **不输出**可导入工作流文件（生成/导入/导出属 L3，v1 不做；只读解析不计入 L3）。

### 6.4 兼容性校验器（v1）

- 检查节点/模型/参数/素材在目标平台是否存在；
- 输出：`compatible` / `degraded` / `incompatible` + 原因 + 人工替代步骤；
- **禁止**简单名称替换（如把某节点直接改名当等价）。

## 7. 分阶段实施

| 阶段 | 内容 | 依赖 | 粗略工作量 | 版本 |
|---|---|---|---|---|
| **甲 契约层** | `ir_spec.md`、`ir validate`、`gen_registry.py`、三注册表、置信度推广 | 无 | 2–4 天 | 2.4.0 |
| **乙 平台骨架** | `creative-platforms/` 三平台、来源闸门、安装物化、命名说明 | 甲 | 3–5 天 | 2.4.x |
| **丙 工作流最小闭环** | `analyze_workflow.py`、Workflow IR 校验、工作流报告、兼容性校验 v1 | 甲、乙 | 4–6 天 | 3.0.0 |
| **丁 模型补齐 + 基准** | 可灵 P0；即梦/海螺/Vidu 可选；`benchmarks/` 7–10 例 | 甲 | 每模型 0.5–1 天；基准 3–5 天 | 3.x |

| **己 发布** | `VERSION`、插件清单、豆包包、README 断言数、Release | 全部 | 0.5 天 | — |

### 7.1 各阶段实现的功能

**甲 · 契约层（2.4.0）**

- **输入**：现有 text / image / video / story JSON（完全不变）。
- **新增能力**：IR v1 定义与 `ir validate`；11 模块视图；全模态置信度标签校验；`gen_registry.py` 与模型/平台/能力三注册表。
- **输出**：校验通过的 IR；元信息卡可展示 IR 版本与能力等级；注册表作为模型/平台/能力的事实源。
- **不包含**：新输入模态、平台适配、工作流解析。
- **用户可见变化**：Prompt 输出与现在一致，但多了可校验的 IR 与一致的注册表；契约错误会明确指出字段/版本问题。

**乙 · 平台骨架（2.4.x）**

- **输入**：现有分析结果 + 用户指定平台（ComfyUI / Runway / LibTV）。
- **新增能力**：三平台五件套、`capability_map.json` schema、来源闸门、安装物化。
- **输出**：平台专用 Prompt 映射、节点/功能映射、不兼容项、人工搭建说明。
- **不包含**：工程文件解析、工作流导入导出、API 调用。
- **用户可见变化**：可以问"这个效果在 ComfyUI 里怎么搭"，得到节点清单与步骤；所有结论标注"已验证/未验证/需人工确认"。

**丙 · 工作流最小闭环（3.0.0）**

- **输入**：新增 ComfyUI API / UI JSON。
- **新增能力**：`analyze_workflow.py`、Workflow IR 校验、`workflow_report.json`、兼容性校验 v1。
- **输出**：节点/连线/模型/采样器/LoRA/ControlNet/自定义节点依赖报告；跨平台兼容性（`compatible` / `degraded` / `incompatible`）+ 人工替代步骤。
- **不包含**：可导入工作流生成、自动执行、闭源工程文件解析。
- **用户可见变化**：丢一个 ComfyUI 工作流 JSON，能读懂它的结构与依赖，并评估迁移到 Runway / LibTV 的可行性。

**丁 · 模型补齐 + 基准（3.x）**

- **输入**：现有模态。
- **新增能力**：可灵模板（P0）；即梦 / 海螺 / Vidu 可选；每个模型配套 `*_sources.md`；`benchmarks/` 7–10 例。
- **输出**：新模型格式 Prompt；语义质量基准与评分 rubric。
- **不包含**：Pika / Leonardo / 万相等 P2 模型。
- **用户可见变化**：目标模型多一个/几个可选；质量有可对比的基线。

**戊 · 降级扩展（可选）**

- **输入**：WAV/PCM 音频；专业软件平台名。
- **新增能力**：响度/静音/节奏确定性信号；PS / Krita / Premiere / DaVinci / 剪映 / AE / Blender / Figma / Canva 的 L1 说明。
- **输出**：音频量化信号 + 专业软件操作说明。
- **不包含**：非 WAV 音频、工程文件解析、自动化执行。
- **用户可见变化**：视频声音设计有量化依据；专业软件有 L1 级操作路径。

**己 · 发布**

- **新增能力**：版本递增、插件清单、豆包包、README 断言数、Release notes。
- **输出**：可分发版本。
- **不包含**：新功能。
- **用户可见变化**：安装/升级路径与发布说明完整。

**阶段独立性**：甲可独立交付；乙依赖甲，但平台文档可先行；丙依赖甲+乙；丁依赖甲；戊可选且独立。每个阶段都可单独发布、单独回滚。

### 7.2 各阶段新增的使用方法

**通用原则**：现有命令与自然语言触发方式全部不变；新增能力一律"追加"，不传新参数时走旧路径；旧 JSON 无 IR 字段时直接通过。

#### 甲 · 契约层

```bash
# 校验一份分析 JSON 是否符合 IR v1（退出码 0 通过 / 4 契约错误）
python prompt-reverse-engineer-skill/scripts/prompt_compiler.py ir validate --analysis analysis.json

# 生成三注册表；--check 只校验是否与源文件一致，不写盘
python tools/gen_registry.py
python tools/gen_registry.py --check
```

- **自然语言**：无新增触发词。Agent 输出元信息卡时多一行 `IR 1.0 · 能力等级 L1/L2`。
- **旧用法**：`all / compile / score / filter / scenes / validate-templates` 全部不变。

#### 乙 · 平台骨架

新增自然语言说法：

| 说法 | 结果 |
|---|---|
| "这个效果在 ComfyUI 里怎么搭？" | 平台 Prompt 映射 + 节点/功能清单 + 搭建步骤 |
| "把这份分析映射到 Runway 工作流" | Runway 步骤映射 + 素材输入输出说明 + 不兼容项 |
| "LibTV 的分镜/角色流程怎么对应？" | 创作步骤映射 + 人工操作说明（不承诺自动执行） |

- **输出固定含**：映射结果、不兼容项、降级方案、置信度标记（已验证 / 未验证 / 需人工确认）。
- **开发者校验**：

```bash
python tools/gen_registry.py --check    # 含平台注册表
python tools/verify.py --filter 平台
```

- **安装**：`python tools/install.py` 不变；copy 模式与豆包包会自动物化 `creative-platforms/`。安装态读不到平台资料时，只输出通用 Prompt 并说明原因。

#### 丙 · 工作流最小闭环

```bash
# 1) 解析 ComfyUI 工作流（API 格式或 UI 格式 JSON）
python prompt-reverse-engineer-skill/scripts/analyze_workflow.py workflow.json -o wf.json

# 2) 生成跨平台兼容性报告与人工搭建说明
python prompt-reverse-engineer-skill/scripts/prompt_compiler.py workflow \
  --report wf.json --target runway --format md
```

新增自然语言说法：

| 说法 | 结果 |
|---|---|
| "拆解这个 ComfyUI 工作流" | 节点/连线/模型/采样器/LoRA/ControlNet/依赖报告 |
| "这个工作流迁到 Runway 要改什么？" | compatible / degraded / incompatible + 替代步骤 |
| "列出缺失的自定义节点和模型" | 依赖清单 + unknown 标记 |

- **不产出**可导入工作流文件；无工作流文件时该分支不启用。

#### 丁 · 模型补齐 + 基准

```bash
# 新模型输出：与现有 --models 用法完全一致
python prompt-reverse-engineer-skill/scripts/prompt_compiler.py all \
  --analysis video.json --models kling
python prompt-reverse-engineer-skill/scripts/prompt_compiler.py all \
  --analysis image.json --models jimeng

# 基准
python tools/benchmarks.py --suite image --check
python tools/verify.py --filter 基准
```

- **自然语言**："也出可灵版" / "出即梦版" / "出 Vidu 版"。
- **回退规则**：未注册的模型名仍回退默认 MJ V8.2 + GPT-5.5/Claude 5.5 双版本，并说明。

#### 戊 · 降级扩展（可选）

```bash

```

新增自然语言说法：

| 说法 | 结果 |
|---|---|
| "分析这段音频的响度和节奏" | 确定性音频信号 + 视频声音设计建议 |
| "Photoshop 里怎么做这个效果" | L1 Prompt + 操作步骤（生成式填充/扩图/蒙版） |

- 非 WAV/PCM 提示用户转码，不内置 ffmpeg；专业软件不给工程文件、不做自动化。

## 9. 明确不做

1. **不重构目录**：不采用原方案第 8 节的 `core/ model_adapters/ platform_adapters/ …`。
2. **不改名**：`platform-adapters/` 保持原样，新增 `creative-platforms/`。
3. **不做 L4**：不调用生成 API、不要求密钥、不建后端。
4. **不解析闭源工程文件**：`.blend`、`.prproj`、`.psd`、`.aep`、剪映工程等。
5. **不一次性铺开 25+ 平台**：先 3 个，跑通规范再扩展。
6. **不建第二套评分引擎**：沿用六维评分 + 审查清单。
7. **不生成可导入工作流**（L3）：v1 只输出分析报告与人工搭建说明。
8. **不把用户具体素材写入技能文档**：示例继续使用仓库中性素材。

## 10. 风险与回滚

| 风险 | 影响 | 缓解 |
|---|---|---|
| IR 文档与实现漂移 | 契约失真 | 注册表/字段映射由脚本生成与断言；`ir_spec.md` 为唯一权威 |
| `creative-platforms/` 安装物化遗漏 | 安装态读不到平台资料 | 乙阶段同时验证 junction / copy / 豆包三种模式；读不到时显式降级 |
| 平台官方资料不可核验 | 产出不可信结论 | 来源闸门；无来源保持 `draft`，不进入注册表 |
| 工作流 JSON 格式变化 | 解析失败 | 读取 `version` 字段；不识别 → 退出码 4 并提示人工处理 |
| 目录增加造成概念混淆 | 用户分不清两个 platform | README 与 `creative-platforms/README.md` 并列说明 |
| 范围蔓延 | 交付延期 | 阶段闸门；每阶段独立提交、独立回滚 |
| 新模型模板质量参差 | 输出漂移 | 每模型先写 `*_sources.md`，再建模板，最后加断言 |

回滚策略：每阶段独立提交、独立 `git revert`；模板与示例同批提交；注册表为生成物，删除不影响运行。
