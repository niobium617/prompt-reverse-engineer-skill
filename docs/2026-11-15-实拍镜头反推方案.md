# 实拍图片/视频逐镜反推方案

> 状态：**已实施**（2026-11-15）
> 版本：v2.4.0 ｜ 基线：`VERSION` 2.3.0、`python tools/verify.py` 53/53
> 目标：让技能能分析真实图片/实拍视频，反推出可直接粘贴的镜头 Prompt
> 定位：在现有双层分析与 Prompt 编译器上做增量扩展，不推翻文本/图片/视频/剧本四条既有分支

---

## 1. 目标与边界

### 1.1 要解决的问题

原有图片模式输出单帧 Prompt，视频模式输出整片分镜脚本；面对实拍素材时：

- 无法说明「这一镜是什么景别、什么机位、怎么运动、持续多久」；
- 整片一段 Prompt 无法逐镜复用，改一镜要重写全片；
- 脚本只给镜头切分点，缺少可核对的焦段/景深/运镜线索；
- Agent 容易把「看不清」写成具体数字，产生幻觉参数。

### 1.2 本次目标（按优先级）

1. 逐镜输出「镜头卡 + 分镜总表」，每镜 Prompt 可独立粘贴。
2. 脚本提供确定性镜头信号，语义判断仍归 Agent。
3. 四个视频模型（Sora 2 / Runway Gen-4.5 / Veo 3.1 / Seedance 2.5）各自渲染，不混用模板。
4. 证据分级：`observed:` / `inferred:` / `unknown:`，未知项不得进正文。
5. 契约可校验：镜头卡错误必须退出 4 并报镜头号，而不是静默产出坏 Prompt。

### 1.3 不做的事

- 不做镜头跟踪、光流测速等重型 CV；运镜轴只做启发式判断。
- 不做音频分析；声音字段来自 Agent 对画面的语义推断或素材自带说明。
- 不新增图片模型；图片反推仍复用既有图像模板（本分支只保证「恰好 1 镜」）。
- 不复制参考项目的代码或整段文案，仅借鉴结构与工作流。

## 2. 总体设计

### 2.1 分支位置

```
用户给实拍图片/视频 + 「反推镜头 / 复刻运镜 / 拆成分镜」
        │
        ├─ L1 脚本：analyze_image.py / analyze_video.py → shot_hints
        ├─ L2 Agent：逐帧复核 → 镜头卡（12 维）+ 分镜总表
        ├─ L3 编译器：prompt_compiler.py shots → 逐镜 × 逐模型 Prompt + 逐镜评分
        └─ 输出：分镜总表 + 镜头卡 + 各模型 Prompt + 逐镜评分 + 镜头审查清单
```

与既有分支共用：统一信封、退出码、六维评分、安全过滤、模板注册机制。

### 2.2 L1 脚本信号

| 信号 | 出处 | 用途 |
|---|---|---|
| `shot_hints.exif` | analyze_image | 真实焦段/光圈/快门/ISO；有 EXIF 时优先 |
| `shot_hints.focal_length_hint` | analyze_image | 无 EXIF 时按景深/视角给「约」值，`basis=dof_inference` |
| `shot_hints.depth_of_field` | analyze_image | 浅/深景深 + `confidence` |
| `shot_hints.letterbox` | analyze_image / analyze_video | 黑边比例，判断画幅与遮幅 |
| `shot_hints.face` | analyze_image | 人脸是否存在，决定能否写人物表情 |
| `shots[].first/mid/last` | analyze_video | 每镜首/中/末关键帧路径，供 Agent 读图 |
| `shots[].motion_axes` | analyze_video | Z 推拉 / X 水平摇移 / Y 升降 / R 旋转 |
| `shots[].camera_move_hint` | analyze_video | 运镜词候选（推/拉/摇/移/跟/升降/旋转/固定） |
| `shots[].dominant_colors` | analyze_video | 逐镜主色，支撑色彩连续性 |
| `shots[].shot_size_hint` / `camera_angle_hint` | analyze_video | 景别/机位候选 |

原则：脚本信号只是**线索**，Agent 必须看帧复核；信号冲突时以画面为准，并在 `evidence` 说明。

### 2.3 L2 镜头卡契约（12 维）

| 字段 | 规则 |
|---|---|
| `shot_no` | 从 1 连续递增；图片恰好 1 镜 |
| `shot_size` | 大远景 / 远景 / 全景 / 中景 / 近景 / 特写 / 大特写 |
| `camera_angle` | 平拍 / 仰拍 / 俯拍 / 低机位 / 过肩 / 第一人称 / 鸟瞰 / 斜角 |
| `camera_move` | 运镜词表；`+` 连接复合运镜，最多两轴；`固定` 不可组合 |
| `duration_s` | > 0；视频各镜之和与 `total_duration` 误差 ≤ 0.5 秒 |
| `subject_action` | 一个可见事件，写主体 + 动作 + 对象 |
| `environment` | 地点/时间/天气/环境细节 |
| `lighting` | 光源方向、性质、明暗关系 |
| `color` | 主色 + 辅助色 + 对比关系 |
| `visual_anchors` | 3–5 个靠前的可复现细节；编译器只强制 ≤ 5 |
| `sound` | 环境声/动作声/音乐；无信息时省略而非编造 |
| `continuity_notes` / `transition` | 跨镜一致项与转场方式 |
| `lens` / `focus` | 有证据才写；无法确认必须省略，不写 `unknown` |
| `evidence` | 必须以 `observed:` / `inferred:` / `unknown:` 开头 |

### 2.4 L3 编译器

```bash
python prompt_compiler.py shots --analysis shot.json \
  [--models sora,runway,veo,seedance] [--dims dims.json | --auto] [--format md]
```

- 未指定 `--models`：默认四个视频模型全出。
- 逐镜 Prompt = 模板 `shot_prefix` + 镜头卡渲染 + `shot_suffix`，各模型独立。
- `--auto`：按字段完整度给近似分，依据列注明「自动近似」；`--dims`：人工评分。
- 无 `shot_style` 的模型自动跳过；全部指定模型都无该段时退出 1。
- 输出含镜头审查清单（6 项，不参与总分）。

### 2.5 退出码

| 码 | 场景 |
|---|---|
| 0 | 成功 |
| 1 | 用法错误；指定的模型都没有 `shot_style` |
| 2 | 输入不可读 |
| 4 | 镜头卡契约错误（编号/枚举/时长/运镜轴/锚点/证据/焦段；图片多镜） |
| 5 | 命中黑名单（`--sanitize` 可过滤后放行） |

## 6. 风险与后续

- 运镜轴为启发式估计，快速摇镜/手持抖动可能误判；以 Agent 看帧复核为准。
- 无 EXIF 的网图只能给「约」焦段，标注 `basis=dof_inference`，不得当真实参数。
- 逐镜渲染依赖模板 `shot_style`；新增视频模型时需同步补该段，否则该模型在 shots 输出中被跳过。
- 后续可选：镜头级转场识别、逐镜音频信号（WAV）、与跨平台升级方案的 IR 契约合并。

## 7. v2.4.1 图片模型扩展（2026-11-16）

初版只覆盖四个视频模型，单张实拍图反推仍需手动换算成图片模型。v2.4.1 把同一份镜头卡契约铺到六个图片模板，图片反推默认一次出六份独立 Prompt。

**模型覆盖**

| 模态 | 模板 | `shot_style` 形态 | 默认集合 |
|---|---|---|---|
| 视频 | Sora 2 / Runway Gen-4.5 / Veo 3.1 / Seedance 2.5 | 时长/画幅/镜头号 + 声音衔接 | `sora,runway,veo,seedance` |
| 图片 | Midjourney V8.2 / SD 3.5 / FLUX.2 [pro] / GPT Image 2.5 / Muse Image 1.0 / Nano Banana Pro | 单帧规格：景别/机位/焦段/焦点 + 正负向或规格书 | `midjourney,stable_diffusion,flux2,gpt_image,muse_image,nano_banana` |

**实现要点**

- `prompt_compiler.py`：新增 `VIDEO_SHOT_MODELS` / `IMAGE_SHOT_MODELS`；`shots` 未指定 `--models` 时按 `modality` 选默认集合；模板校验允许图片模态带 `shot_style`。
- 六个图片模板各补 `shot_style`：MJ 用 `/imagine prompt:` + `--ar/--v`；SD 分 `Positive/Negative` + 采样参数；FLUX.2 保持无负向；GPT Image / Nano Banana 用分字段规格书；Muse 用完整中文句。
- 新增金标 `tools/fixtures/semantic_shot_reverse_image.json`（单镜、EXIF 85mm、f/1.8）。
- `verify.py` 新增 `镜头反推/图片六模型渲染`（57 → 58），并修正「无 shot_style 退出 1」用例改用文本模型 `deepseek`。
- 文档同步：`prompt_framework.md` 2.6、`shot_reverse_rules.md` 第七节、`SKILL.md` 默认模型表、README 1.2/3.4/3.6/验证表。

**验证**

**边界**：图片模板不含时长/声音/衔接占位符，单帧 Prompt 不写视频句式；`shot_style` 只认镜头卡字段与 `default_params`，新增字段需同时改 2.6 节契约。
