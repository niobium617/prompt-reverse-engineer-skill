# AI 短片镜头逆向复用升级方案（项目适配版）

> 状态：**待评审**（2026-11-19）
> 来源：`AI短片镜头逆向复用_Skill专项升级方案_V1.0.docx`（2026-11-18）
> 基线：`VERSION` 3.2.0；`python tools/verify.py` 74/74；`benchmarks/` 10 例；16 模型（13 个模板含 `shot_style`）
> 定位：在现有**实拍镜头分支**上增量扩展，不新增分支、不新增编译器、不改既有必填字段
> 结论：架构契合 9/10，能力覆盖约 6/10。采纳两条主线（**复用计划**、**关键帧时间轴**），改造 4 类契约冲突（共 9 条），明确不采纳 8 项。

---

## 1. 目标与边界

### 1.1 要解决的问题

现有实拍镜头分支（v2.4.0 / v2.4.1）已经能把素材反推为「镜头卡 + 分镜表 + 逐镜 Prompt」，但还不能回答短片刻画里更高频的问题：

- 我只想改人物性别，别的都别动——哪些字段要保留、哪些要联动改？
- 这一镜的结尾怎么接到下一镜开头？
- 同一镜想换三种景别/机位，怎么保证核心风格不漂？
- 生成结果有瑕疵，下一轮最小修改是什么？

### 1.2 本次目标（按优先级）

1. **镜头级复用计划**：Baseline + Delta + Preserve + Dependency，输出「已修改 / 保留 / 必须联动 / 无法保证」四栏清单。
2. **关键帧时间轴**：L1 从固定均匀抽样升级为「均匀 + 变化驱动加密 + 镜头边界保护」，为 L2 提供带时间戳的证据帧。
3. **五类复用模式**：复刻 / 局部修改 / 变体 / 延续 / 修复，按模式校验必填字段。
4. **连续性资料**：角色、场景、风格资料以「用户可确认的单次 JSON 字段」存在，不做持久化。
5. **模型适配复用现有机制**：继续使用 `shot_style` 模板与 `capability_registry.json`，不新增能力文档。

### 1.3 不做的事

- 不做视频生成器、剪辑软件或平台自动执行（无 L4）。
- 不把语义判断塞进 L1（“人物转头”“摄影机推进”仍归 L2）。
- 不新增独立 Prompt 编译器、不新增 `schemas/` 目录、不重构模板目录。
- 不为未核验模型（如 Wan）写死能力；先按用户实际使用频率评估。
- 不实现“修复闭环”的自动 diff——它与 `tasks/todo.md` 阶段 4 合并，留到 P2。

## 4. 总体设计

```
用户：素材 + 目标（复刻 / 局部修改 / 变体 / 延续 / 修复）
        │
        ├─ L1  analyze_video.py
        │     元数据 / 镜头边界 / 变化曲线 / 关键帧（首·中·末 + 变化帧）
        │     运镜轴 / 逐镜色彩 / 黑边 / 景别·机位提示
        │
        ├─ L2  Agent（Read 原图或关键帧复核）
        │     镜头卡（12 维必填 + 新增可选字段）
        │     action_timeline / 起止状态 / 证据三档
        │     reuse_plan：baseline / delta / preserve / dependent / uncontrollable
        │
        ├─ L3  prompt_compiler.py shots
        │     契约校验（按 reuse_mode 追加必填）
        │     复用计划 + 四栏清单
        │     逐镜 × 逐模型 Prompt（沿用 shot_style 模板）
        │     逐镜评分 + 审查清单（新增 3 项）
        │
        └─ 输出：分镜总表 / 镜头卡 / 复用计划 / 逐模 Prompt / 评分 / 审查清单
```

与现有分支共用：统一信封、退出码、六维评分、安全过滤、模板自动注册、IR 1.0 可选层。

## 5. 阶段 A（P0）：镜头复用计划

### 5.1 字段契约（全部扁平）

**镜头组新增可选字段**（`semantic_analysis` 顶层）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `reuse_mode` | string | `replicate` / `local_edit` / `variant` / `continuation` / `repair` |
| `baseline_prompt` | string | 原镜头基准描述，只写可复用部分 |
| `prompt_delta` | string[] | 只表达用户要求的改动，一条一件事 |
| `dependent_updates` | string[] | 因改动必须联动的项：阴影、倒影、褶皱、遮挡、接触关系 |
| `uncontrollable` | string[] | 模型无法保证的项（构图锁定、运镜严格复现等） |
| `preserve_constraints` | string[] | **复用已有字段**；未授权改动默认进这里 |
| `forbidden_changes` | string[] | **复用已有字段**；明确禁止的变化 |
| `modification_scope` | string[] | **复用已有字段**；修复/编辑的改动边界 |
| `target_changes` | string[] | **复用已有字段**；编辑类目标（与 `prompt_delta` 二选一，见 5.2） |
| `continuation_from` | string | 延续模式：上一镜头结束状态 |
| `variant_of` | string | 变体模式：原镜头标识（如 `shot_01`） |
| `variant_axis` | string | 变体模式：`shot_size` / `camera_angle` / `camera_move` / `action_intensity` / `lighting_weather` |

**镜头卡新增可选字段**（`shots[i]`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `action_timeline` | string[] | 动作时间轴，如 `["0–1.5 秒站立", "1.5–3 秒转身", "3–5 秒推进并完成视线变化"]` |
| `start_state` | string | 镜头开始状态：人物位置、朝向、视线、道具状态 |
| `end_state` | string | 镜头结束状态；延续模式以它为下一镜的输入 |
| `subject_appearance` | string | 主体外观与服装（跨镜一致性抓手） |
| `subject_facing` | string | 主体朝向与运动方向 |
| `composition_design` | string | 视觉中心、留白、前景/中景/背景、遮挡关系 |
| `material_texture` | string | 材质、颗粒、写实/动画质感 |
| `audio_cues` | string[] | 声音及其时间位置（可选） |

> 所有新字段均为**可选**，不进入 `SHOT_REQUIRED` / `PROGRAM_REQUIRED`。不声明 `reuse_mode` 时，`shots` 输出必须与 v3.2.0 逐字节一致。

### 5.2 模式必填规则（`validate_shots`）

| `reuse_mode` | 追加必填 | 缺失处理 |
|---|---|---|
| `replicate` | 无 | 旧行为 |
| `local_edit` | `baseline_prompt`、`prompt_delta`、`preserve_constraints` | 退出码 4，列出缺失字段 |
| `variant` | `variant_of`、`variant_axis`（枚举校验） | 退出码 4 |
| `continuation` | `continuation_from`，且第 1 镜有 `start_state` | 退出码 4 |
| `repair` | `modification_scope`、`target_changes` 或 `prompt_delta` | 退出码 4 |

规则补充：

- `prompt_delta` 与 `preserve_constraints` 归一化后若存在包含关系，不给退出码，写入 `warnings` 并在审查清单标「待复核」——由 Agent 指出冲突并给最小调整，不静默覆盖。
- `repair` 模式不得重写 `baseline_prompt` 以外的场景/角色设定；规则写入 `shot_reverse_rules.md`。

### 5.3 编译器行为（`prompt_compiler.py`）

1. `SHOT_STRING_FIELDS` 增加 `start_state` / `end_state` / `subject_appearance` / `subject_facing` / `composition_design` / `material_texture`；`SHOT_LIST_FIELDS` 增加 `action_timeline` / `audio_cues`。
2. `NEW_STRING_FIELDS` 增加 `reuse_mode` / `baseline_prompt` / `continuation_from` / `variant_of` / `variant_axis`；`NEW_LIST_FIELDS` 增加 `prompt_delta` / `dependent_updates` / `uncontrollable`。
3. `validate_shots()` 增加 5.2 模式校验；`reuse_mode` 不在枚举内退出码 4。
4. `cmd_shots()` 在输出中**仅在声明 `reuse_mode` 时**增加 `reuse_plan`：

```json
{
  "reuse_plan": {
    "mode": "local_edit",
    "baseline_prompt": "...",
    "delta": ["男性替换为女性，穿白色西装"],
    "preserve": ["构图", "运镜", "动作时序", "雨夜氛围"],
    "dependent_updates": ["服装褶皱", "阴影", "地面倒影"],
    "uncontrollable": ["模型无法严格锁定构图"],
    "manifest": {
      "changed": ["..."],
      "preserved": ["..."],
      "dependent": ["..."],
      "uncontrollable": ["..."]
    }
  }
}
```

5. Markdown 在「逐镜头卡片」与「逐镜 Prompt」之间新增 **复用计划** 一节：模式、基准、四栏表。
6. 审查清单由 6 项扩到 9 项：
   - `reuse_contract`：模式必填字段是否齐全；
   - `reuse_conflict`：Delta 与 Preserve 是否冲突；
   - `continuity_state`：延续模式下 `continuation_from` 与 `start_state` 是否都写明。
   新项不参与总分，沿用现有 `review_checklist` 结构。

### 5.4 文档与示例

- `references/prompt_framework.md` §2.6：补 5.1 字段表、5.2 校验规则、输出 `reuse_plan` 契约。
- `references/shot_reverse_rules.md`：新增「复用计划五模式」「联动项判定表」「冲突处理」「修复模式边界」；不新建 `prompt_delta_rules.md` / `continuity_rules.md`，避免同一分支规则碎片化。
- `SKILL.md`：§2 实拍分支补一句复用模式；§4 镜头反推输出格式插入「复用计划」；§7 索引说明。
- 新增 `tools/fixtures/semantic_shot_reuse.json`（local_edit 金标）与 `assets/examples/shot_reuse_example/`。
- 新增 `benchmarks/shot_reuse/shot-local-edit.json` 与 `shot-continuation.json`，各带 `gold.md` 与至少 3 条语义标准。

### 5.5 验收

- 旧 fixture（`semantic_shot_reverse.json`、`semantic_shot_reverse_image.json`）输出逐字节不变。
- `local_edit` 缺 `preserve_constraints` → 退出码 4，报字段名。
- `reuse_plan.manifest` 四栏与输入字段一一对应。
- Delta 与 Preserve 冲突时输出 `warnings`，不阻断。
- `verify.py` +4（契约字段、模式必填、manifest、旧输出不变）；`benchmarks --check` +2。

## 6. 阶段 B（P0）：关键帧时间轴增强

### 6.1 L1 输出（`analyze_video.py`）

1. 第一遍顺带记录每个抽样点的直方图变化量，输出 `change_curve: [{t, score}]`（保留现有逐秒亮度曲线）。
2. 在每个镜头内部取变化峰值，**额外抽 1–2 帧**，命名 `shot_NN_change_M.jpg`；距镜头边界不足一个抽样间隔的位置不加密（边界保护）。
3. 每镜新增 `change_frames: [{path, timestamp_s, score}]`；保留首/中/末关键帧。
4. 新增 `--max-keyframes`（默认 24，整片上限）：超出时按变化分数保留最高者，其余只记索引不落盘。
5. 沿用两遍顺序解码、`--workdir`、重复运行清理（现有 `shot_*.jpg` glob 已覆盖新命名）。

### 6.2 L2 责任

- `action_timeline` 由 Agent 结合变化帧与时间戳撰写，L1 只给客观变化区间，不判断“转身/推进/情绪”。
- 每项时间轴结论必须在 `evidence` 中引用 `observed:` 或 `inferred:`。

### 6.3 验收

- 变化曲线时间戳单调递增，长度与抽样点一致。
- 关键帧总数不超过 `--max-keyframes`；边界附近无变化帧。
- 同一输入两次运行输出一致；临时文件清理不变。
- `verify.py` +3（变化曲线、帧数上限、边界保护）。

## 7. 阶段 C（P1）：连续性资料与变体 / 延续

### 7.1 连续性资料（无状态）

新增镜头组可选数组字段，每项一句话：

| 字段 | 示例 |
|---|---|
| `character_profile` | `"林晓：短发、黑色风衣、左眉疤痕；用户已确认"` |
| `scene_profile` | `"便利店外街角：霓虹招牌、湿滑地面、夜间小雨"` |
| `style_profile` | `"冷蓝主调、高对比、轻颗粒、写实摄影"` |

规则：

- 只能来自用户确认或本片多镜一致观察，不得由单镜推断直接升级为“项目设定”。
- 不落盘、不跨会话保存；每次分析随 JSON 传递。
- 渲染时只进入审查说明，不默认塞进 Prompt 正文；需要时由 Agent 显式引用。

### 7.2 变体

- Agent 按 `variant_axis` 生成多个分析文件，分别运行 `shots`；不扩编译器并行能力。
- 编译器只校验 `variant_of` / `variant_axis` 并原样输出，便于汇总。
- 输出说明写清「同一基准镜头的 N 个变体」，避免用户误当 N 个独立镜头。

### 7.3 延续

- 复用现有能力：Seedance `first_last_frame` / `video_extension`，Kling 首尾帧，其他模型按 `shot_style` 渲染新镜头。
- 规则补充：`continuation_from` 与首镜 `start_state` 对齐人物位置、朝向、视线、运动方向、服装、场景布局、光线方向。
- 审查项 `continuity_state` 只做“是否写明”的确定性检查，语义冲突由 Agent 提示。

### 7.4 模型适配

- 继续以 `config/capability_registry.json` 为单一来源，不新建 `video_model_capabilities.md`。
- Wan 等未核验模型暂不写入；确需支持时按“新增模型 = 新增模板文件”零代码路径处理，并补来源索引与 `last_verified`。
- 同一镜头区分「重新生成 / 参考帧生成 / 直接编辑」由 `reuse_mode` + 现有 `task_type` 共同表达，不新增第三套枚举。

### 7.5 验收

- 资料卡字段不改变既有输出（未提供时逐字节一致）。
- 变体文件 `shot_no` 在各自文件内连续。
- `verify.py` +2（资料卡/变体字段、延续校验）；`benchmarks --check` +1（变体或延续用例）。

## 9. 不采纳清单

| 提案内容 | 处理 | 理由 |
|---|---|---|

| 数值 `confidence` | 保留三档标签 | 伪精度，且与 evidence 校验冲突 |
| `assets/templates/video_models/`、`shot_reuse/`、`schemas/` | 不建 | 现有扁平模板自动注册 + 文档契约已覆盖 |
| 独立 Prompt 编译器 | 不建 | 提案自身也反对；编译器只做渲染 |
| `video_model_capabilities.md` | 不建 | 注册表是单一来源 |
| 资料卡持久化 | 降级为单次 JSON 可选字段 | 违背“无后端状态” |
| Wan / 更多模型 | 暂缓 | 先按实际使用频率核验 |
| 把语义判断塞进 L1 | 不采纳 | 与双层边界冲突 |

## 11. 风险与边界

| 风险 | 控制 |
|---|---|
| 变化驱动加密产生过多关键帧 | `--max-keyframes` 硬上限；按变化分数裁剪；边界不加密 |
| `reuse_mode` 与 `task_type` / `kind` 枚举重叠 | `reuse_mode` 只做分析层编排，不进入 `TASK_KINDS`，避免两套枚举打架 |
| 变体与 `shot_no` 连续性冲突 | 不扩编译器并行；按变体分文件运行 |
| 资料卡滑向全局状态 | 只允许单次 JSON 字段；文档明确“用户确认后才可复用” |
| 新字段破坏旧输出 | 全部可选；不声明 `reuse_mode` 时输出逐字节不变，纳入 verify 断言 |
| 模型能力被写死 | 以注册表与官方来源为准；未核验模型不写入 |
| 评分被误当复刻准确率 | 沿用现有口径提醒：评分衡量 Prompt 结构质量，不是与原片的相似度 |
