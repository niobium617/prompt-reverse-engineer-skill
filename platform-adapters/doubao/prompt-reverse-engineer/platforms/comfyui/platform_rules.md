# ComfyUI 平台规则

> 核验日期：2026-11-17 ｜ 状态：`verified` ｜ 本 Skill 能力等级：L2（Prompt + 参数）；工作流只读分析（L3）自 3.0.0 起提供
> 官方来源与未核验边界见 [sources.md](sources.md)。

## 1. 平台定位

ComfyUI 是**节点式生成式 AI 应用**：一张工作流就是一张有向图，节点负责加载模型、编码文本、采样、解码与保存。官方文档同时覆盖本地部署与 Comfy Cloud。工作流可保存为 JSON，也可通过本地服务或云端 API 提交。

对本 Skill 的含义：ComfyUI 不是「一个模型」，而是**模型、节点与参数的编排环境**。同一个 Prompt 在不同工作流里落点不同，因此映射必须说明「写到哪个节点、哪些参数进节点、哪些依赖本机安装」。

## 2. 官方工作流格式（已验证）

官方 Workflow JSON 规范当前为 **1.0（Latest）**，并保留旧版 **0.4**。UI 保存格式的核心字段：

| 字段 | 含义 |
|---|---|
| `version` | 工作流格式版本（1.0 / 0.4） |
| `nodes` | 节点数组（含 `id`、类型、位置、`widgets_values` 等） |
| `links` | 连线数组，引用源节点与输出槽位 |
| `groups` | 画布分组 |

API 格式是另一套结构：顶层以**节点 ID 为键**，每个节点包含 `class_type` 与 `inputs`。官方文档明确：API 格式**省略 UI 元数据**（位置、颜色、分组等），适合程序提交；浏览器保存格式适合继续在画布中编辑。

导出方式（官方文档）：`File → Export Workflow (API)` 得到 API 格式；普通保存得到 UI 格式。

### 对本 Skill 的约束

- **工作流只读解析自 3.0.0 起提供**：`analyze_workflow.py` 只读 API/UI JSON，`prompt_compiler.py workflow` 出兼容性报告；仍不生成、不导入、不导出可导入工作流。
- 不生成、不导入、不导出任何工作流 JSON；不声称可「直接跑通」。
- API 格式与 UI 格式**不可逐字段互换**：UI 格式含布局与 `widgets_values`，API 格式不含。涉及参数位置时必须人工在画布上确认。
- 节点类名会随版本与自定义节点变化。本目录中的类名一律视为**需人工确认**，以本机节点定义（如 `/object_info` 返回）为准。

## 3. 输入、输出与模型

| 项 | 官方确认情况 |
|---|---|
| 输入模态 | 图片、视频、音频、3D（官方文档导航与内置节点分类） |
| 输出模态 | 图片、视频、音频、3D；由工作流末端节点决定 |
| 内置模型 | 不固定：模型权重由用户安装；官方文档提供加载器与采样节点 |
| 自定义节点 | 官方支持；第三方节点包可扩展节点类型 |
| 版本 | 未统一锁定；节点与前端版本均可能影响工作流兼容性（`unknown`） |

因此 `capability_map.json` 的 `models` 为空数组，并在 `dependencies.custom_nodes` 说明依赖需按工作流逐个登记。

## 4. 本 Skill 的使用规则

### 4.1 Prompt 落点

统一 Prompt 进入 ComfyUI 时通常拆成：

- **正向文本**：进入文本编码节点（常见为 `CLIPTextEncode`，需人工确认）；
- **负向文本**：进入另一个文本编码节点，或由支持负向的采样节点接收；
- **结构化字段**（画幅、步数、CFG、种子、采样器、调度器）：进入对应节点的 `inputs` / `widgets_values`，**不写进 Prompt 正文**；
- **参考图 / 蒙版 / ControlNet**：由图像加载、预处理与控制节点承担，属于工作流依赖，不是 Prompt 文本。

### 4.2 参数

以下参数在 ComfyUI 中属于**工作流级**，映射时必须单独列出并标注来源：

| 统一字段 | ComfyUI 落点 | 置信度 |
|---|---|---|
| 画幅 / 分辨率 | 空 latent 或图像尺寸节点 | 需人工确认 |
| 采样步数 / CFG | 采样器节点输入 | 需人工确认 |
| 种子 | 采样器节点输入 | 需人工确认 |
| 采样器 / 调度器 | 采样器节点输入 | 需人工确认 |
| 去噪强度 | 图生图 / 重绘类工作流 | 需人工确认 |
| LoRA 权重 | LoRA 加载节点 | 需人工确认 |
| ControlNet 强度 | 控制网应用节点 | 需人工确认 |

未在本机工作流中确认的参数，一律写「需人工确认」，不得填默认值冒充官方默认。

### 4.3 工作流依赖

回答「怎么搭」时应同时给出：

1. 节点/功能清单（按数据流向排序）；
2. 每个节点的作用与关键输入；
3. 需要的模型权重、LoRA、ControlNet、自定义节点；
4. 缺失依赖的处理：标 `unknown`，给人工安装方向，不自动下载；
5. 无法确认的节点类名或端口，标「需人工确认」。

## 5. 不兼容与降级

| 情况 | 处理 |
|---|---|
| 用户给的是闭源工程文件（`.blend` / `.psd` / `.prproj` 等） | 明确不支持，请用户提供 ComfyUI 公开 JSON 或文字描述 |
| 工作流含未安装的自定义节点 | 节点映射标 `unknown`；给节点包名称（若已知）与人工安装建议 |
| 工作流引用的模型权重缺失 | 标 `unknown`；列出文件名，不自动下载 |
| 只有成品图/视频、没有工作流 | 全部制作过程结论只能标 `inferred` / `unknown` |
| 安装态读不到 `platforms/` | 只输出通用 Prompt，并说明未加载 ComfyUI 平台资料 |
| 工作流 JSON 结构非法（悬空连线/成环/非 API/UI） | `analyze_workflow.py` 退出码 4，不输出解析结论；请用户检查导出文件 |
| 要把工作流迁到其他平台 | `prompt_compiler.py workflow` 输出逐节点 `compatible/degraded/incompatible`、文件迁移结论与手工重建步骤；不生成、不导入可导入文件 |

## 6. 安全边界

- 不执行工作流，不启动 ComfyUI 服务，不调用 `/prompt` 等接口；
- 不安装自定义节点、不下载模型、不修改用户环境；
- 不把网页端/云端功能等同于本 Skill 的能力；
- 不输出可导入的工作流文件，不承诺「一键运行」。
